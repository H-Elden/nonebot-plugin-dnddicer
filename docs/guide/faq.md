# 群管理与 FAQ

本页汇总群级配置、与宿主机器人协同的注意事项与常见问题。

## 群默认骰面（.dset，群主/管理员）

`.dset` 设置本群的默认骰面：掷骰（`.r`）中**省略面数的裸 `D`/`3D`** 会使用本群默认骰面（全局默认 d20）。可设置任意掷骰表达式（`100`、`2d6+3` 均可）。

```text
你发送：.dset 100
骰娘回复：本群默认掷骰表达式已改为D100。

你发送：.dset
骰娘回复：当前默认掷骰表达式为D100。使用 .dset [表达式] 进行修改。
```

设置后裸 `D` 的行为（示例群默认 d6）：

```text
你发送：.r d+2
骰娘回复：艾琳 的掷骰结果为 1D6+2=[4]+2=6
```

| 场景 | 回复 |
| --- | --- |
| 非群主/管理员修改 | `仅群主或管理员可以设置群默认骰面。` |
| 无效表达式（如 1 面骰） | `默认掷骰表达式无效：默认骰面数至少为2` |
| 私聊使用 | `该指令仅在群聊中可用。` |

## 群聊服务开关（.bot，白名单）

- 群聊服务**默认关闭**：未开启的群仅 `.bot` 可用，其余命令静默不响应（事件交给宿主其他插件，不会刷屏报错）；
- `.bot on / off` 仅限群聊、仅**群主/管理员**，且群聊中 `.bot` 系列需 **@ 本机器人**；
- **私聊不受开关限制**，任何命令直接可用。

完整说明与示例见 [快速开始 - 群聊使用](./quickstart.md#群聊使用先开启本群服务白名单)。

## 与宿主机器人协同

### 命令起始符（默认只用句号）

本插件命令默认以 `.` / `。` 开头，**不**使用宿主 `COMMAND_START`（NoneBot 默认含 `/`）。

原因：`/help`、`/bot` 等常见单词命令会与本插件同时命中，造成行为不可控。

- 需要斜杠触发时：设置 `dnddicer_use_host_command_starts=true`（此后 `/.help` 同样有效）；
- 开启后若仍出现命令被"抢答"，调小 `dnddicer_command_priority`（默认 10，越小越优先）。

### 响应不到时的排查顺序

1. **群聊**：本群服务是否开启？（`.bot` 查询；未开启只会得到无响应或 `.bot` 的回复）
2. `.bot` 系列：是否 @ 了机器人？@ 位于开头或结尾均可。
3. 命令是否以 `.`/`。` 开头？（斜杠需配置开启）
4. 私聊直连测试：如果私聊正常而群聊无响应，基本是白名单开关问题。

## 数据存储与隐私

| 项目 | 说明 |
| --- | --- |
| 存储位置 | NoneBot localstore 数据目录下的 `nonebot_plugin_dnddicer/`（可用 `LOCALSTORE_DATA_DIR` 调整） |
| 内容 | 角色卡（群+QQ 键）、HP、先攻表、群配置、服务开关名单——全部本地 JSON，**不上传任何服务器** |
| 清理 | 删除对应 JSON 文件或发送 `.角色卡清除` / `.hp del` / `.init clr` |

## 规则范围 FAQ

**Q：支持 COC 或 d100 体系吗？**
不支持。屠龙骰专精 DND5e/5r：不做 COC 属性生成/理智、不做 `.mode` 规则切换。因此大成功/大失败只围绕 d20，`.r 1d100` 也不会播报。

**Q：`.r` 与检定点命令（`.力量检定`）的区别？**
`.r` 手动写完整表达式；检定点命令自动代入角色卡上的调整值/熟练/额外加值（先攻检定还会自动入先攻表）。有卡时推荐用点命令。

**Q：检定的"成功/失败"怎么算？**
检定点命令只掷出裸数值（d20+加值），**不判定 DC**——由 DM 与玩家比较。大成功/大失败只是 20/1 的演出播报（攻击检定中 20=重击、1=必定失误符合 5e 规则）。

**Q：`.r exp`、`.r a/n` 模式为什么提示未实现？**
属于 DicePP 的期望值计算与特殊判定模式，不在第一期范围，显式提示而非静默。

**Q：同一条消息能命中多个插件命令怎么办？**
通过事件优先级协同：本插件默认优先级 10（高于 NoneBot 默认 1000），同一消息上先于普通监听器处理；需要让位时把 `dnddicer_command_priority` 调大。

**Q：怪物/NPC 血量与多目标列表有吗？**
有。先 `.ri 名称` 把 NPC 加入先攻表，再用 `.hp 名称 10/10` 记录血量（先攻列表
与 `.hp list` 都会展示）；同名 NPC 在新战斗中入表时自动回满，需要跨战斗延续
血量用 `.npc 持久 名称`。详见 [HP 管理](./hp-rest.md) 的「NPC / 怪物血量」。

**Q：玩家不在场，DM 怎么代操作他的角色卡？**
把 **@该成员** 写在目标位置即可（@ 与名称可混写，分隔符 `;` 或空白）：

| 场景 | 写法 |
| --- | --- |
| 结算 HP | `.hp @玩家 -4d6`、`.hp @玩家 20/30`、`.hp @玩家;地精 -d4`（AOE）、`.hp @玩家`（查看） |
| 长休收尾 | `.长休 @玩家` |
| 代掷先攻 | `.ri+3 @玩家`（条目名取角色卡名并与该玩家绑定，重掷替换、回合提醒同款） |
| 定位先攻条目 | `.init del @玩家`、`.init first @玩家`、`.init swap @玩家/兽人`、`.回合 @玩家` |
| 查看 | `.角色卡 @玩家`（整卡）、`.状态 @玩家` |
| 代掷检定 | `.力量豁免 @玩家`、`.2#敏捷攻击优势 @玩家`、`.先攻检定 @玩家` |

@ 的目标需已在本群建卡（否则真 @ 提示引导建卡）。注意 @ 要写在目标位置：
`.hp -4d6 @玩家`、`@玩家 .hp -4d6` 这类游离写法**不执行**并回纠正示例——这是刻意
设计（此前会静默按发送者自己结算，容易误伤）。查看他人卡对任何人开放，但
`.角色卡记录`/`.角色卡清除` **仅本人**可执行。
